# Проект: SwipeSwap backend, выпуск v1.0

## 1. Паспорт проекта

**Участники:** Батсайхан Ширээт, Балабанов Максим.
**Продукт:** SwipeSwap — backend мобильной платформы бартерного обмена вещами без денег (ASP.NET Core 9, PostgreSQL, Redis, JWT).
**Планируемый выпуск:** `v1.0`
**Исходное состояние:** тег `baseline` = коммит `96e1706`.
**Репозиторий:** https://github.com/shireet/SwipeSwap

### Контекст и пользователи

Продукт разработан студентами в учебном проекте. Пользователи — мобильный клиент (в репозиторий не входит) и люди, обменивающиеся вещами: они регистрируются, публикуют вещи, предлагают обмен и договариваются в чате. Для них важны конфиденциальность аккаунта и переписки и то, что обменом и вещами управляет только владелец. Решение о выпуске принимают оба участника; при расхождении выпуск откладывается.

### Границы

**В проект входит:**

- backend;
- PostgreSQL и Redis в том виде, как их поднимает `compose.yaml`;
- `Dockerfile`, `compose.yaml`, GitHub Actions (`.github/workflows/ci.yml`);
- тесты: 89 unit-тестов;
- зависимости (`Directory.Packages.props`) и конфигурация (`appsettings.json`).

**За пределами проекта:**

- мобильный клиент;
- производственная инфраструктура, TLS, reverse proxy, облако;
- реальные пользователи и данные;
- рекомендации товаров: `Items/recommended` возвращает мок-данные.

### Компоненты, взаимодействия и границы доверия

- Клиент → REST API (`/api/v1/...`): основная граница доверия, всё из запроса недоверенное; аутентификация по JWT (HS256, срок 60 минут), refresh-токен действует 14 дней.
- API → PostgreSQL: пользователи (пароли в виде BCrypt-хеша), вещи, обмены, чаты, сообщения, refresh-токены. Миграции применяются при старте приложения.
- Источник кода → сборка: NuGet-зависимости, базовые образы Docker, GitHub Actions.
- Секреты (ключ JWT, пароль БД) читаются из `appsettings.json` и переменных окружения.

### Активы и существенные риски

- **Актив:** учётные записи и токены (`AuthenticateController`, `JwtService`, таблица refresh-токенов).
  **Что может произойти:** подделка токена при компрометации ключа JWT; попадание паролей и токенов в логи или в чужие руки.
  **Почему это существенно:** захват аккаунта и действия от чужого имени.
- **Актив:** обмены и вещи пользователей (`ExchangesController`, `ItemsController`).
  **Что может произойти:** действия над чужим обменом или вещью при слабой проверке прав доступа к объектам.
  **Почему это существенно:** это основная функция продукта, на ней держится доверие между пользователями.
- **Актив:** переписка в чатах и данные профиля (`ChatController`, `UserController`).
  **Что может произойти:** чтение чужих сообщений или персональных данных другими пользователями.
  **Почему это существенно:** нарушение конфиденциальности.
- **Актив:** секреты и конфигурация развёртывания (ключ подписи JWT, пароль БД; `appsettings.json`, `compose.yaml`, образ Docker).
  **Что может произойти:** утечка секретов через конфигурацию, образ или журнал.
  **Почему это существенно:** с ними можно выпускать валидные токены и обращаться к БД.
- **Актив:** цепочка поставки (NuGet-пакеты, образы, CI).
  **Что может произойти:** в выпуск попадают зависимости с известными уязвимостями.
  **Почему это существенно:** выпуск нельзя обосновать без проверки зависимостей.

- [x] тесты (89 unit-тестов);
- [x] конфигурации (`appsettings.json`, `compose.yaml`, `Dockerfile`);
- [x] CI/CD (GitHub Actions: restore, build, test);

**Недоступно:** мобильный клиент, производственная инфраструктура и реальные данные.
**Конфиденциальность:** все данные учебные. Все значения секретов в проекте учебные, реальные секреты не используются. Нельзя публиковать личные данные участников, кроме ФИО и учебных адресов.
**Почему проект выполним:** продукт небольшой и запускается локально за минуты. Есть тесты и CI. Проверки (поиск секретов, анализ зависимостей, тесты авторизации) выполняются локально и без внешних сервисов. Улучшение (например, убрать секреты из конфигурации или добавить проверку прав в обменах) невелико по объёму и проверяется повторным запуском тех же проверок.
